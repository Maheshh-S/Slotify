# Slotify - Developer Journal

Personal log of building Slotify from scratch. Not for public consumption - just my notes.

## Day 1 (Oct 24) - Project Setup

Morning: Decided to build a slot booking system with optimistic locking. Been reading about concurrency patterns - pessimistic vs optimistic. Went with optimistic since we want horizontal scaling without distributed locks.

Set up Spring Boot 3.2.4 with Java 21. Maven wrapper generated. Added all starters upfront - web, data-jpa, security, validation, cache, flyway, postgresql, h2, swagger, jwt, lombok. Figured better to have them now than add later.

Afternoon: Configured pom.xml with groupId=slotify.tech.mahesh, artifactId=tech.mahesh. JAR will be tech.mahesh.jar. Spent too long deciding on package name - settled on tech.mahesh.slotify.

## Day 2 (Oct 25) - Config & Main Class

Morning: Created application.yml and application-prod.yml. Dev uses local PostgreSQL, prod uses env vars. Hikari pool size 20. Flyway enabled with baseline-on-migrate. Cache type simple for now.

Main class: SlotifyApplication with @EnableCaching and @EnableScheduling. Forced UTC timezone in @PostConstruct - learned the hard way that timezone bugs are nasty in distributed systems.

Added Lombok and JWT dependencies to pom.xml.

## Day 3 (Oct 26) - Entities & Repositories

Morning: Created enums first - UserRole (USER, ADMIN), SeatStatus (AVAILABLE, LOCKED, BOOKED), BookingStatus (PENDING, CONFIRMED, CANCELLED). Simple but important to get right.

Entities: User, Event, Seat, Booking. Key decision: Seat has @Version for optimistic locking. Composite index on (status, locked_at) for the cleanup scheduler. Booking links User, Event, Seat - all @ManyToOne LAZY.

Repositories: SeatRepository is the critical one. lockSeat() uses version check in WHERE clause - pure optimistic locking, no SELECT FOR UPDATE. findExpiredLocks() for the scheduler.

Commits: 2

## Day 4 (Oct 27) - JWT Security

Morning: Implemented JWT from scratch. JwtTokenProvider with HS256, 1-hour expiry. Claims include email and role. JwtAuthenticationFilter extends OncePerRequestFilter - resolves Bearer token, validates, sets SecurityContext.

CustomUserDetailsService loads User by email, builds Spring Security UserDetails. BCryptPasswordEncoder for passwords.

Afternoon: SecurityConfig - stateless sessions, CSRF disabled, permitAll for /auth/**, /swagger-ui/**, /v3/api-docs/**, /actuator/**. JWT filter before UsernamePasswordAuthenticationFilter.

Auth DTOs: AuthRequest, RegisterRequest, AuthResponse with validation annotations.

Commits: 2

## Day 5 (Oct 28) - Booking Service (Core)

Morning: This is the heart. BookingService with @Transactional. lockSeat() calls SeatRepository.lockSeat() - returns rows affected (0 or 1). If 0, throw SeatNotAvailableException. confirmBooking() and cancelBooking() are idempotent - check ownership, validate status transitions.

GlobalExceptionHandler maps OptimisticLockingFailureException -> 409 Conflict with proper error response. Also handles SeatNotAvailableException -> 409, BookingConflictException -> 409.

Afternoon: SeatLockCleanupService with @Scheduled(fixedRate=300000) - every 5 minutes finds seats LOCKED longer than 5 minutes and releases them back to AVAILABLE. Uses findExpiredLocks() query.

Commits: 2

## Day 6 (Oct 29) - Controllers

Morning: AuthController - POST /auth/register, POST /auth/login. Simple, returns JWT.

EventController - GET /events (paginated), GET /events/{id}. Uses EntityGraph to avoid N+1.

Afternoon: BookingController - POST /bookings/lock-seat, POST /bookings/{id}/confirm, POST /bookings/{id}/cancel, GET /bookings (paginated, user's bookings). EntityGraph on seat->event for efficient loading. PageResponse DTO for consistent pagination.

## Day 10 (Nov 2) - k6 Load Testing

Morning: Wrote k6 script with 3 scenarios. Contention race: 50 VUs hitting same seat - should get 1 success, 49 409s. Sustained read: 20 VUs for 15s on /events. Spike: 0->30 VUs instantly on auth endpoints.

Afternoon: Ran tests locally. Contention test: 1% success, 99% 409 - exactly as expected. Sustained read: all under 300ms. Spike: all under 500ms. Happy with results.
